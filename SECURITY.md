# 🛡️ Security Policy & Vulnerability Disclosure

ETHIO-CYBERGUARD takes the security and integrity of our defensive platform seriously. We appreciate responsible disclosure of security vulnerabilities from the research community.

---

## Supported Versions

| Version | Supported |
| :--- | :---: |
| 1.1.x | ✅ |
| 1.0.x | ⚠️ Critical Fixes Only |
| < 1.0 | ❌ End of Life |

---

## Reporting a Vulnerability

**Please do NOT file public GitHub issues for security vulnerabilities.**

To report a vulnerability:
1. Open a confidential security advisory directly on GitHub via:
   👉 **[Security Advisory Submission](https://github.com/AbeniYirgalem/ETHIO-CYBERGUARD/security/advisories/new)**
2. Or contact the maintainers via email:
   - **Lead Developer**: Abenezer Yirgalem
   - **Emergency Security Contact**: `security@ethio-cyberguard.org`

### What to Include:
- A clear description of the vulnerability (e.g. prompt injection escape, authentication bypass, SQLi, SSRF).
- Step-by-step reproduction steps or proof-of-concept (PoC).
- The impacted module or API route (`apps/api`, `services/ai/`, `services/phishing/`).
- Suggested remediation or patch, if available.

### Disclosure Timeline:
- **Acknowledgement**: Within 48 hours.
- **Triage & Assessment**: Within 5 business days.
- **Patch & Public Advisory**: Coordinated within 30 days of initial report.
